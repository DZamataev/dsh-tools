# session-artifacts: задача, решение, проверка

Дата: 2026-10-29. Статус: реализовано, коммиты `7f3ea50` и `132ef31`. Плагин: [`plugins/session-artifacts/`](../../plugins/session-artifacts/README.md).

## Задача

В DSH нет места, где собраны документы сессии: планы, брифы, отчёты, которые агент создаёт, в том числе в gitignored-папках (`.planning/`, `tmp/`). Агент не всегда ссылается на них в переписке, и в длинной сессии план приходится искать по всей переписке.

## Как это решают другие харнессы (на 2026-10-29)

- **Claude Desktop, вкладка Code:** сбоку от чата есть панель сведений о сессии («session rail»), плюс отдельные панели, в том числе Plan ([docs](https://code.claude.com/docs/en/desktop)). Claude Code пишет планы в отдельную папку (`plansDirectory`, [settings](https://code.claude.com/docs/en/settings-reference)).
- **Cursor:** Plan Mode сохраняет план отдельным markdown-файлом, кнопка «Save to workspace» переносит его в проект ([docs](https://cursor.com/docs/agent/plan-mode)).
- **ChatGPT desktop:** сайдбар чата показывает план, источники и созданные файлы ([docs](https://www.codex-docs.com/en/docs/artifacts-viewer)).
- **Codex app:** такой панели нет, есть открытый запрос [openai/codex#40663](https://github.com/openai/codex/issues/40663). Его довод совпадает с нашим: файлы собирать по реальным записям агента, а не по `git status`, потому что сгенерированные файлы часто в `.gitignore`.

## Что было в самом DSH

- `present` (событие `deliverables/presented`) сохраняется в журнале, но появляется, только если агент сам вызвал инструмент.
- Карточка изменений за ход (`workspace-changes`) видит и gitignored-файлы, но она привязана к одному ходу, а сводка живёт только в памяти Host: событие `workspace/changes` в журнале несёт лишь номер хода, путей в нём нет.
- Сводки документов по всей сессии не было.

## Решение

Плагин `@local/dsh-session-artifacts`: вкладка «Артефакты» в правом сайдбаре (тип страницы в `ctx.sidebarRightTabs`) и кнопка в шапке сессии.

- **Источник данных** — весь журнал сессии через `ctx.sessionQuery.observeSession`, поэтому список переживает перезапуск DSH. Ничего не индексируется и не хранится отдельно.
- **Что попадает в список:** файлы из `write`, `edit`, `str_replace_editor`, патчей (`*** Begin Patch` … `*** End Patch` в инструментах из `patchTools`, путь от `workdir` вызова), записей изнутри `run_code` (`tool/ptc-dispatch`), события `deliverables/presented` с описанием и документов, упомянутых в ответах агента, если файл есть на диске. Отдельно — планы из `exit_plan_mode` со статусом «одобрен / отклонён / ждёт решения».
- **Документы** — только расширения из конфига: md, txt, pdf, html, office, csv, изображения.
- **Интерфейс:** фильтр по типу с количеством, поиск по имени и пути, «скрыть отсутствующие», сортировка (выбор запоминается); клик открывает файл во встроенном превью сайдбара, отдельная кнопка копирует путь; пока идёт ход, список обновляется сам. Тексты на русском, английском и китайском.
- **Host:** маршрут `POST /api/session-artifacts.list`, доступ только владельцу. Извлечение — чистая функция в `artifacts.js`, проверка файлов — `stat` по 4 одновременно, `realpath` только для склейки синонимов одного файла, кэш извлечения по сессии и позиции журнала.

Подробности, конфиг и ограничения — в [README плагина](../../plugins/session-artifacts/README.md).

## Как шла работа

1. Host и клиент параллельно писали два субагента DeepSeek V4.1 Flash по общему описанию контракта.
2. Два независимых ревью на Opus 5.5 нашли две серьёзные ошибки: регулярное выражение для ссылок могло надолго повесить весь Host, а вкладки разных сессий делили состояние и могли показать чужие файлы. Мелких находок было около тридцати; DeepSeek исправил все.
3. Финальная проверка на Opus подтвердила исправления и нашла ещё одну: в папке, открытой через симлинк, показывался не тот путь. Исправлено.
4. Ревью Codex (GPT-6.1 Sol) серьёзных проблем не нашло. Исправлены четыре мелкие: путь из патча считался не от `workdir` bash-команды; один файл под разными путями занимал несколько мест в лимите; после выгрузки плагина в памяти оставались старые данные; после фильтрации Tab переставал попадать в список.

## Проверка

- Тесты: Host `node --test tests/` 51/51, клиент `node --test tests-client/` 33/33 (jsdom с настоящим React).
- На реальной сессии с планами в `.planning/` вкладка нашла 10 документов, включая `pending-decisions.html` с описанием из `present` и оба брифа из `tmp/`.
- На тестовом инстансе `~/.dsh-dev` агент создал два файла и в ответе их не назвал; оба появились во вкладке, клик открыл превью.

## Установка

`plugins/install.sh` подключает плагин в профили сам, в том числе как post-deploy хук `deploy.sh` из dz-dsh-rollout. Без деплоя: закрыть DSH и выполнить `~/dev/dsh-tools/plugins/install.sh`.

## Ограничения

- Не видны файлы, созданные только shell-командой без упоминания в ответе.
- Не видны записи субагентов и тиммейтов: у них свои журналы.
- В SSH-профилях существование файла проверяется на локальном диске, поэтому файлы будут показаны как отсутствующие.
- Иконку нарисовал агент, дизайнер её не смотрел.
