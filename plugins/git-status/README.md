# git-status (DSH)

Ветка git текущей сессии в строке статуса под полем ввода (слот `conversation.composer.dock`, первой, перед счётчиками хода). Плашка показывает имя ветки, точку цвета текста, если есть незакоммиченные изменения, и `↑N ↓M` относительно upstream. В detached HEAD показывается короткий sha, вне репозитория — имя папки. Подсказка при наведении — полный путь.

Клик открывает панель:

- имя рабочей папки, путь (домашняя папка сокращена до `~`) и кнопка «Копировать путь» — копирует полный путь в буфер обмена;
- размер папки (`du -sk`), с кнопкой «Пересчитать»; папки без прав на чтение не считаются, и это помечено;
- ветка, upstream с `↑/↓`, последний коммит (sha, заголовок, давность, автор; при наведении на автора — его email), корень репозитория, если папка лежит глубже;
- счётчики изменений (в индексе, изменено, новых, конфликтов) и список в формате `git status --short`, не длиннее `maxStatusLines` строк;
- кнопка «Подтянуть» в строке Upstream: `git fetch`, затем `git merge --ff-only @{upstream}` — только перемотка вперёд. Отказ с объяснением, если ветка разошлась с upstream (слить или сделать rebase предлагается вручную), если merge перезаписал бы локальные изменения (называются файлы), если HEAD отсоединён или у ветки нет upstream. Локальные изменения в файлах, которых перемотка не касается, остаются. Пока агент выполняет ход, кнопка выключена. В одном репозитории одновременно идёт только одна синхронизация (pull или push); начатая доводится до конца, даже если панель закрыли. ssh запускается с `BatchMode=yes` (если не задан свой `GIT_SSH_COMMAND`), поэтому ключ с паролем без агента даёт ошибку fetch, а не зависание;
- кнопка «Отправить» там же — `git push` без force. С upstream: `git fetch` этого remote, затем `git push <remote> HEAD:<ветка upstream>`; если ветка отстаёт от upstream или разошлась с ним, отправка не начинается (сначала «Подтянуть» или слияние вручную), если отправлять нечего — так и пишет. Если у ветки задан отдельный push-remote (`branch.<имя>.pushRemote` или `remote.pushDefault`), отличный от upstream, кнопка отказывает: такой расклад отправляйте из терминала. Без upstream: ветка публикуется под тем же именем в единственный remote (или в `remote.pushDefault`) с `--set-upstream`; при нескольких remote или без remote — отказ с подсказкой команды. Отказ remote (защищённая ветка, хук `pre-receive`) показывается с причиной из `git push --porcelain`. Хуки `pre-push` выполняются как обычно, поэтому предел `pushTimeoutMs` больше, чем у pull. Пока агент выполняет ход, кнопка выключена;
- кнопка «Ревью в Zed» рядом со счётчиками: открывает все изменения относительно HEAD (включая новые файлы, по `--untracked-files=all`, не больше `maxReviewFiles`) в одном multi-diff окне Zed. Слева — версия из HEAD (снимок во временной папке `dsh-git-review`, снимки старше суток удаляются при следующем ревью), справа — настоящий файл рабочего дерева, поэтому правки справа сохраняются в репозиторий. У нового файла левая сторона пустая, у удалённого — правая.

Папка — текущая рабочая папка сессии: проекция `workingDirectory`, которая учитывает переход в worktree; без неё — `cwd` из заголовка сессии. Браузер передаёт только `sessionId`, поэтому запрос не может запустить git или du в произвольном пути.

- Host (`index.js`, `git.js`): маршруты `POST /api/git-status.summary`, `.size`, `.review`, `.pull` и `.push` через `connection.fetch` (доступ только владельцу, как у остальных `/api`). Папка берётся через `sessionQuery.observeSession`. Всё запускается без shell. Опрос только читает: `git --no-optional-locks status --porcelain=v2 --branch -z`, `rev-parse --show-toplevel`, `log -1` (sha, заголовок, время, имя и email автора), с `GIT_OPTIONAL_LOCKS=0`, поэтому опрос не мешает git, который в это время запускает агент. Размер кэшируется на `sizeCacheTtlMs` по папке; один `du` на папку за раз, и он доводится до конца, даже если панель закрыли, так что при следующем открытии результат уже готов.
- Ревью: Zed CLI раскрывает пары папок в `--diff` в пары файлов, а в одно окно их собирает, если хотя бы одна пара — папки. Плагин передаёт пару пустых папок как этот переключатель и затем по паре «снимок HEAD — рабочий файл» на каждый изменённый файл; так справа остаются настоящие пути (обход папок в Zed пропустил бы симлинки). Zed ищется в `zedPath`, а если он пуст — в `/usr/local/bin/zed`, `/opt/homebrew/bin/zed` и `/Applications/Zed.app/Contents/MacOS/cli`: у Desktop, запущенного из Finder, `PATH` без `/usr/local/bin`.
- Client (`client.js`): опрашивает сводку каждые `pollMs`, пока вкладка видна, а также сразу при смене папки, по окончании хода агента и при возврате фокуса в окно. Размер запрашивается только при открытии панели.

Изменения Host-части и `client.js` подхватываются после перезапуска DSH.

Настройки в `cordis.patch.yml` профиля (значения по умолчанию):

```yaml
- id: git-status
  config:
    gitPath: git              # исполняемый файл git
    duPath: du                # исполняемый файл du
    gitTimeoutMs: 5000        # предел на каждый вызов git
    sizeTimeoutMs: 30000      # предел на du
    sizeCacheTtlMs: 120000    # сколько держать посчитанный размер
    maxStatusLines: 20        # строк git status в панели
    pollMs: 10000             # период опроса из браузера
    zedPath: ''               # Zed CLI; пусто — искать в обычных местах
    zedTimeoutMs: 20000       # предел на запуск Zed CLI
    maxReviewFiles: 300       # сколько изменённых файлов открывать в ревью
    pullTimeoutMs: 60000      # предел на git fetch и на git merge --ff-only
    pushTimeoutMs: 120000     # предел на git push (включая хуки pre-push)
```

Тесты: `node --test tests/` (разбор вывода git на литералах, маршруты на временном репозитории, pull и push против голого `origin` со вторым клоном (включая отказ хука `pre-receive` и общий замок) и ревью с подменным Zed CLI).
