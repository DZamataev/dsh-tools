# session-find (DSH)

Поиск по переписке открытой сессии: Cmd+F (Ctrl+F на Windows и Linux) или кнопка с лупой в шапке сессии открывают панель справа сверху. Поиск идёт по Enter, кнопка `.*` включает регулярные выражения. Совпадения показываются списком с ролью, номером хода, временем и фрагментами текста; к сообщению в чате список не переходит.

Ищется только переписка: сообщения человека (`user/message` с `source.kind === 'user'`) и текст ответов ассистента (`assistant/message`). Размышления модели, вызовы и результаты инструментов, системные вставки (инструкции, напоминания) в поиск не попадают. Читается весь лог сессии, а не отрисованная часть чата; индекс не строится, другие сессии не читаются.

- Host (`index.js`, `search.js`, `run.js`, `match-worker.js`): маршрут `POST /api/session-find.search` через `connection.fetch` (доступ только владельцу, как у остальных маршрутов `/api`). Каждый запрос читает один лог через `sessionQuery.observeSession` (живая сессия, если открыта, иначе сохранённый лог) и ищет в отдельном worker-потоке. По истечении `timeoutMs` поток останавливается, так что зависший регэксп не блокирует Host.
- Client (`client.js`): кнопка в слоте `conversation.session.header.utilities` (order 15), панель в `shell.overlay`. Cmd+F зарегистрирован как фиксированное действие (`shortcuts.registerFixed` + `observeFixedInput`), поэтому одинаково работает в вебе и в десктопе и виден в справочнике клавиш. Срабатывает только при открытой сессии, вне терминала и модальных окон; иначе браузер оставляет свой поиск. При переключении на другую сессию панель закрывается.

Простой запрос ищется без учёта регистра, а любая последовательность пробелов в нём совпадает с любой последовательностью пробельных символов в тексте. Регэксп компилируется с флагами `gimu`: без учёта регистра, `^`/`$` по строкам.

Настройки в `cordis.patch.yml` профиля (значения по умолчанию):

```yaml
- id: session-find
  config:
    maxQueryLength: 1000     # длина запроса
    maxResults: 300          # сколько сообщений показывать (счётчики считают все)
    snippetsPerMessage: 3    # фрагментов на сообщение
    contextBefore: 60        # символов контекста до совпадения
    contextAfter: 140        # и после
    maxMatchChars: 200       # длинное совпадение обрезается
    timeoutMs: 10000         # предел времени на поиск
```

Проверки: `node --test tests/`.
