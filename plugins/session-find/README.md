# session-find (DSH)

Поиск по переписке открытой сессии: Cmd+F (Ctrl+F на Windows и Linux) или кнопка с лупой в шапке сессии открывают панель справа сверху. Результаты обновляются по мере ввода, через 300 мс после паузы (простой запрос короче двух символов ищется только по Enter). Совпадения показываются списком с ролью, номером хода, временем и фрагментами текста.

Запрос:

- Слова без кавычек ищутся в любом порядке: сообщение подходит, если в нём есть каждое слово. «Фраза в кавычках» ищется целиком; незакрытая кавычка тянется до конца запроса.
- Кнопка `.*` включает регулярное выражение (флаги `gimu`: без учёта регистра, `^`/`$` по строкам). Неверный регэксп показывается сразу, без запроса к Host.
- Регистр не важен, ё и е считаются одной буквой: перед сравнением ё сводится к е и в тексте, и в запросе (буква заменяется одна на одну, поэтому фрагменты и подсветка показывают исходное написание). Пробелы внутри фразы совпадают с любой последовательностью пробельных символов.
- Под строкой поиска: фильтр «Все / Мои / Агент» и порядок «Сначала новые / Сначала старые» (по умолчанию новые). Фильтр и порядок применяются на Host до обрезки списка, так что «сначала новые» показывает действительно последние совпадения. Режим `.*`, фильтр и порядок запоминаются в `localStorage`.

Клавиши в поле ввода: ↑/↓ выбирают результат, Enter открывает выбранный (или сразу ищет, если список устарел), ↑ в пустом поле перебирает историю — последние 20 запросов, сохранённых по Enter или при открытии результата. Esc закрывает окно контекста, затем панель.

Клик по совпадению или Enter открывает в той же панели окно контекста: найденное сообщение целиком и по три реплики до и после, взятые из лога. Сообщение длиннее `maxMessageChars` обрезается: найденное — вокруг первого совпадения, соседние — с конца; обрезанная сторона помечена. «Раньше» и «Позже» добавляют ещё по пять реплик. Текст отображается как Markdown (компонентом `MarkdownText`, как в чате), совпадения подсвечены, панель сразу прокручена к первому совпадению в найденном сообщении. ↓, Enter и кнопка «вниз» ведут к найденному сообщению ниже (позже в переписке), ↑, Shift+Enter и кнопка «вверх» — выше, при любом порядке списка; счётчик «3 из 17» тоже считает по порядку переписки. У каждого сообщения кнопка ⧉ копирует его исходный текст. «К результатам» или Esc возвращают к списку. Сам чат панель не прокручивает.

Ищется только переписка: сообщения человека (`user/message` с `source.kind === 'user'`) и текст ответов агента (`assistant/message`). Размышления модели, вызовы и результаты инструментов, системные вставки (инструкции, напоминания) в поиск и в окно контекста не попадают. Читается весь лог сессии, а не отрисованная часть чата; индекс не строится, другие сессии не читаются. Каждый запрос (в том числе при наборе) заново читает лог сессии; прежний запрос при этом отменяется.

- Host (`index.js`, `search.js`, `run.js`, `match-worker.js`): маршруты `POST /api/session-find.search` и `POST /api/session-find.context` через `connection.fetch` (доступ только владельцу, как у остальных маршрутов `/api`). Каждый запрос читает один лог через `sessionQuery.observeSession` (живая сессия, если открыта, иначе сохранённый лог). Запрос пользователя выполняется только в отдельном worker-потоке: поиск, а для окна контекста — список совпавших строк в показанных сообщениях и место первого совпадения в найденном. По истечении `timeoutMs` поток останавливается, так что зависший регэксп не блокирует Host; окно контекста тогда показывается без подсветки. После пустого совпадения поиск сдвигается на целый символ (эмодзи не зацикливают регэксп). Текстовые блоки сообщений берутся как есть, без обрезки пробелов. Идущие запросы получают сигнал отмены плагина: при выгрузке он срабатывает, а выгрузка ждёт завершения запросов и их потоков.
- Client (`client.js`): кнопка в слоте `conversation.session.header.utilities` (order 15), панель в `shell.overlay`. Cmd+F зарегистрирован как фиксированное действие (`shortcuts.registerFixed` + `observeFixedInput`), поэтому одинаково работает в вебе и в десктопе и виден в справочнике клавиш. Срабатывает только при открытой сессии, вне терминала и модальных окон; иначе браузер оставляет свой поиск. При переключении на другую сессию панель закрывается. Браузер не выполняет запрос пользователя над текстом: он только проверяет, что регэксп компилируется, а подсвечивает присланные Host совпавшие строки как обычный текст (`foldText`, `advanceIndex` и `queryTerms` повторены в клиенте и должны совпадать с `search.js`). В режиме регэкспа строка подсвечивается везде, где встречается в показанных сообщениях, даже если, например, якорь `^` сработал только в одном месте. Прокрутка при этом идёт к настоящему первому совпадению: Host сообщает, каким по счёту среди подсвеченных мест найденного сообщения оно стоит. Каждый результат поиска несёт смещение первого совпадения; клиент передаёт его в окно контекста, поэтому длинное сообщение обрезается вокруг совпадения, даже если подсветка не уложилась в `timeoutMs`.
- Markdown рисует `MarkdownText` из `@deepseek-ai/dsh-client-ui-primitives`. Это не контракт для плагинов и может измениться с обновлением DSH; если компонента нет или он падает, сообщение показывается простым текстом. Подсветка в окне контекста идёт через CSS Custom Highlight API и DOM не меняет; цвет правила `::highlight()` берётся готовым значением из токена темы, потому что токены объявлены на `body`. После отложенной подсветки кода совпадения размечаются заново. Фраза, разбитая разметкой на несколько узлов (например, частично жирная), не подсвечивается.

Изменения Host-части и `client.js` подхватываются только после перезапуска DSH: HMR в профиле по умолчанию не следит за файлами, а сервер читает клиентский бандл один раз.

Настройки в `cordis.patch.yml` профиля (значения по умолчанию):

```yaml
- id: session-find
  config:
    maxQueryLength: 1000       # длина запроса
    maxResults: 300            # сколько сообщений показывать (счётчики считают все)
    snippetsPerMessage: 3      # фрагментов на сообщение
    contextBefore: 60          # символов контекста до совпадения
    contextAfter: 140          # и после
    maxMatchChars: 200         # длинное совпадение обрезается
    timeoutMs: 10000           # предел времени на поиск
    maxContextMessages: 100    # сколько реплик до и после можно запросить в окно контекста
    maxMessageChars: 200000    # длиннее — сообщение в окне контекста обрезается
    maxHighlightStrings: 200   # сколько разных совпавших строк подсвечивать в окне контекста
    maxHighlightChars: 1000    # более длинные совпадения не подсвечиваются
```

Проверки: `node --test tests/`.
