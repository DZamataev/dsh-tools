# session-artifacts (DSH)

Артефакты открытой сессии: вкладка «Артефакты» в правой панели со списком документов, которые сессия создала, изменила, показала или упомянула за весь свой журнал, а не за один ход, и с планами, которые она показала. Список переживает перезапуск DSH: он каждый раз выводится из журнала сессии, ничего не индексируется и не хранится отдельно. Открыть вкладку можно кнопкой в шапке сессии (в ряду утилит, order 16) или карточкой на странице-подсказке правой панели; клик по строке или Enter открывает файл во встроенном просмотре правой панели, отдельная кнопка копирует абсолютный путь.

## Что попадает в список

Операции вынимаются из журнала по порядку; путь берётся из аргументов инструмента или события. Относительные пути разрешаются от рабочей папки, действовавшей в момент операции (её меняет `working-directory/change`), `~/` раскрывается в домашнюю папку. В список идут только расширения из настроенных (`extensions`); пути, у которых любой сегмент входит в `excludeSegments`, отбрасываются.

| Источник | Событие журнала | Путь |
|---|---|---|
| `write`, `edit` | вызов инструмента с этими именами | `file_path` |
| `edit` | `str_replace_editor` с `command` = `create` (считается созданием), `str_replace`, `insert`, `undo_edit` | `path` |
| `patch` | аргументы инструмента из `patchTools`, если в них есть цельный блок `*** Begin Patch` … `*** End Patch`; заголовки `*** Add File:`, `*** Update File:`, `*** Move to:`; `*** Delete File:` и исходная сторона `Move to:` помечают файл удалённым | путь из заголовка |
| `present` | `deliverables/presented` | `files[].path`, сохраняется `description` |
| `mention` | текст ответов агента: ссылки `[x](path)`, пути в обратных кавычках и голые пути | только существующие файлы с документным расширением, отключается `includeMentions` |

Вызовы инструментов и вложенные отправки через `run_code` разбираются одинаково. Вызов, у которого парный `tool/result` сообщает об ошибке или отказе, не считается; прерванный ход с исходом «неизвестно» считается, потому что операция могла пройти; вызов без результата ещё выполняется — тоже считается. Два написания одного файла (симлинк, другой регистр пути) сводятся в одну строку: `path` сохраняет написание из журнала, а канонический путь файла (realpath) используется только для того, чтобы найти такие дубли.

У каждой строки есть набор источников (`sources`), признак создания (`created` — первая операция создала файл), признак удаления (`deleted` — последняя операция удалила или перенесла его), число операций (`ops`), последнее описание из `present` и время. `lastSeq` и `lastTime` — последняя операция записи, правки или патча, а если их не было — последнее появление в `present` или в тексте; по этому же времени строки упорядочены. Файл, который упомянут только в тексте и которого нет на диске, в ответ не попадает; остальные отсутствующие файлы остаются в списке как пропавшие. Упоминания-одиночки обрезаются до `maxMentionCandidates` (остаются самые свежие).

Планы из режима планирования — это вызовы `exit_plan_mode` с markdown в аргументе `plan`: заголовок (первый заголовок Markdown или первая строка), ход, время, текст до `maxPlanChars` и решение по плану — `approved`, `rejected` или `pending`.

## Как выглядит

- Строка поиска по имени и пути, чипы типов с количеством (только те типы, что есть в сессии, плюс «Другое» для незнакомого типа), переключатель «Скрыть пропавшие», порядок «Сначала свежие / По имени». Чипы переносятся на новую строку, а не уезжают в скрытую прокрутку. Чип, переключатель и порядок запоминаются в `localStorage` (`session-artifacts:prefs`); запрос, прокрутка и раскрытые планы живут в записи таба и переживают переключение вкладок, но не перезапуск.
- Строка: бейдж типа (расширение), имя, папка, бейджи «новый / изменён / показан / удалён / пропал», последнее описание из `present` (две строки) и относительное время последнего изменения. Папка обрезается с начала: хвост пути остаётся видимым (компонент `PathLabel`, а без него — своя обрезка с середины), полный путь в подсказке. На узкой панели время переезжает на строку папки.
- Пропавший файл приглушён и не открывается (`aria-disabled`), но остаётся в порядке обхода с клавиатуры, а его путь по-прежнему копируется. Удалённый или перенесённый файл помечается нейтральным бейджем «удалён» вместо «пропал».
- Кнопка копирования называет файл в своём имени («Копировать путь: spec.md»), подтверждает копирование галочкой и один раз объявляет результат через вежливый live-region.
- Строки — одна остановка Tab: ↑/↓ ходят по списку, Enter открывает. Иконки-кнопки несут локализованные имена, а при наличии общего компонента — и подсказку с сочетанием клавиш.
- Планы — сворачиваемая секция над списком документов: заголовок, ход, время и бейдж решения; раскрытая строка рисует текст через `MarkdownText`. Если планов нет, секции нет.
- Состояния: пока данных нет, вместо списка показываются строки-заготовки (одна загрузка, без текста «загружаю»); ошибка показывается на месте списка и держится до первого успешного чтения, поэтому повторяющаяся неудача не переобъявляется; пустое состояние различает «в сессии ещё нет документов» и «под фильтр ничего не подходит».
- Время и порядок имён считаются `Intl` для активного языка приложения, числа — через `Intl.PluralRules` («1 документ», «2 документа», «5 документов»). Ошибки называют то, что случилось: «журнал этой сессии не найден», «нет связи с сервером», «плагин выгружается», а если маршрута в Host нет (ответ 404 без JSON) — «серверная часть плагина не загружена — перезапустите DSH».

Список перечитывается при показе вкладки, по кнопке «Обновить», по команде обновления вкладки (кнопка и сочетание самой панели), в конце хода сессии и каждые 5 с, пока ход идёт и вкладка видна. Явный запрос (кнопка, команда, «Повторить», конец хода) отменяет текущее чтение и начинает новое; фоновый опрос, наоборот, уступает уже идущему запросу. Индикатор занятости показывается только у явного запроса. Чтение отменяется при скрытии вкладки, её закрытии и смене сессии, а запись таба существует ровно столько, сколько живёт сам таб.

## Устройство

- Host (`index.js`, `artifacts.js`): маршрут `POST /api/session-artifacts.list` через `connection.fetch` (доступ только владельцу, как у остальных маршрутов `/api`). Запрос читает один журнал через `sessionQuery.observeSession` (живая сессия, если открыта, иначе сохранённый журнал) и отдаёт `ok`, `cwd`, `artifacts`, `plans`, `truncated`. Извлечение — чистая функция `collectArtifacts` без файловой системы; `index.js` добавляет к каждой строке `exists`/`size`/`mtime` (не больше 4 параллельных `stat`, любая ошибка кроме `ENOENT` — это тоже «файла нет»), сводит одинаковые файлы и отдаёт не больше `maxArtifacts` записей. Повторный запрос при неизменном журнале отвечает из кэша извлечения. Ошибки как у остальных маршрутов: `400 bad-request`, `404 not-found`, `499 aborted`, `500 read-failed`, `503 unloading`. Первый ответ значит «журнала этой сессии нет» (клиент так и пишет), `503` — «плагин выгружается»; а если маршрута в Host нет вовсе, он отвечает обычным текстом с кодом 404, и клиент показывает «серверная часть плагина не загружена — перезапустите DSH». Запросы в полёте получают сигнал отмены плагина: при выгрузке он срабатывает, а выгрузка ждёт их завершения.
- Client (`client.js`): тип вкладки в правой панели, зарегистрированный двумя шагами — `ctx.sidebarRightTabs.register({ id, kind, title, guide })` и тело в слоте `sidebar.right.pane.tab` (ключ — `id` типа), заголовок чипа в `sidebar.right.pane.tab.title`, кнопка в слоте `conversation.session.header.utilities` (order 16) вызывает `ctx.sidebarRight.openTab('session-artifacts')` и подсвечивается, когда у этой сессии уже есть открытая вкладка. Строка открывает файл через `tab.actions.openResource(...)`, то есть через штатный просмотр правой панели; обновление вкладки привязывается через `tab.actions.bindCommands({ refresh })`.
- Состояние ведётся отдельно для каждой сессии: рендерер вызывает внедряемое лицо плагина один раз на привязку сессии, и у каждой сессии свои записи табов и свои запросы. Идентификаторы табов уникальны только внутри сессии, поэтому общее хранилище на всех смешало бы строки двух сессий.
- Адрес файла — `dsh-resource://file/session/<sessionId>/<путь>`; `fileAddressFor` из `@deepseek-ai/dsh-util-workspace-path` повторён в `client.js` дословно, потому что пакет не входит в таблицу модулей браузера и обычный JS-плагин не может его потребовать. Копию нужно держать в согласии с исходником.
- `MarkdownText`, `PathLabel` и `Tooltip` берутся из `@deepseek-ai/dsh-client-ui-primitives`. Это не контракт для плагинов и может измениться с обновлением DSH: без них план показывается простым текстом, папка обрезается вручную, а у иконки-кнопки остаётся `title`.
- Все строки интерфейса — в словарях en/zh/ru через `ctx.locale.register`; стили — только на токенах темы (`var(--dsw-…)`). Узкая панель не переполняется: чипы переносятся, строки обрезаются, ряд опций переносится, время уходит в строку папки, а кольцо фокуса берёт цвет из общего правила.

Изменения Host-части и `client.js` подхватываются только после перезапуска DSH: HMR в профиле по умолчанию не следит за файлами, а сервер читает клиентский бандл один раз.

## Настройки

`cordis.patch.yml` профиля (значения по умолчанию):

```yaml
- id: session-artifacts
  config:
    extensions:            # тип → расширения (строчные, без точки); указанные типы заменяются, остальные остаются по умолчанию
      markdown: [md, markdown, mdx]
      text: [txt, rst, adoc, org, log]
      pdf: [pdf]
      html: [html, htm]
      office: [docx, doc, xlsx, xls, pptx, ppt, odt, ods, odp, rtf]
      data: [csv, tsv]
      image: [png, jpg, jpeg, gif, webp, svg]
    includeMentions: true        # учитывать пути, упомянутые в ответах агента
    maxArtifacts: 500            # больше — список обрезается, ответ помечает truncated
    maxPlanChars: 200000         # сколько символов плана хранить
    maxMentionScanChars: 2000000 # сколько всего символов ответов агента просматривать на упоминания
    maxMentionCandidates: 300    # сколько самых свежих упоминаний-одиночек оставить
    patchTools: [apply_patch, bash, run_code]   # инструменты, в аргументах которых ищется блок apply_patch (полная замена списка)
    excludeSegments: [node_modules, .git]       # сегменты пути, которые не попадают в список (полная замена списка)
```

Неизвестный ключ, неизвестный тип, расширение, занятое двумя типами, кривое расширение, имя инструмента с пробелом или сегмент со слэшем, число вне диапазона — ошибка загрузки со списком проблем, а не молчаливое игнорирование.

## Ограничения

- Учитываются только файлы, названные инструментами записи, правки и патча, `deliverables/presented` и упоминания в тексте агента. Файлы, созданные только командами оболочки (`mv`, `cp`, генераторы, `git checkout`), в список не попадают: патч ищется лишь в аргументах `patchTools` и только внутри блока `*** Begin Patch` … `*** End Patch`.
- Дочерние сессии (сабагенты и тимейты) не читаются: список принадлежит журналу той сессии, которая открыта.
- Содержимое файлов не сохраняется: показывается текущее состояние на диске, а `exists`/`size`/`mtime` — на момент запроса. Файл, изменённый после последней операции в журнале, в списке не обновится сам по себе, но пропавший файл будет виден как пропавший.
- «Создан» — приближение: первая операция создала файл. Правка файла, который существовал до сессии, помечается как правка, а не как создание. «Удалён» включает перенос: исходная сторона `Move to:` считается удалённой.
- Упоминания ищутся только в тексте ответов агента (до `maxMentionScanChars`, самые свежие — первыми) и только для файлов, которые существуют на диске; путь, названный в размышлениях, вызове инструмента или команде оболочки, не считается.
- Упоминание в тексте, разбитое разметкой Markdown на несколько узлов, может не распознаться как путь.
- Решение по плану восстанавливается из журнала: «отклонён» — проваленная или отклонённая проверка, «ждёт решения» — результата ещё нет, «одобрен» — всё остальное.
- Копия `fileAddressFor` в `client.js` не обновляется вместе с пакетом `@deepseek-ai/dsh-util-workspace-path`: при изменении грамматики адреса её нужно поправить здесь.
- Адрес открытия строится от рабочей папки сессии (именно от неё протокол `file` разрешает относительный путь), а `relPath` в ответе считается от последней действовавшей рабочей папки. После `working-directory/change` это разные корни: подпись папки в строке берётся из `relPath` как есть, а открытие идёт по абсолютному пути из журнала и всегда попадает в тот же файл.

Проверки: `node --test tests/` (Host) и `node --test tests-client/` (клиент в jsdom с настоящим React; React и jsdom берутся из pnpm-хранилища чекаута DSH, путь в `DSH_REPO`, по умолчанию `~/dev/deepseek-harness`).

Изменения Host-части и `client.js` подхватываются только после перезапуска DSH.
