# device-reservations (DSH)

Иконка в доке под полем ввода (рядом с provider-limits). По клику — панель: тестовые устройства из реестра rn-looky (`~/.looky/ledger.json`), сгруппированные по проекту (копии rn-looky), который их забронировал; у каждого — статус (`сборка · looky` при живом лизе, `бронь`, `свободно`), подключено ли оно (или запущен ли симулятор) и зависшие лизы. Данные собираются при каждом открытии панели и по кнопке «Обновить»; фонового опроса нет.

Клик по устройству раскрывает управление:

- **Забронировать** за выбранным проектом — свободное устройство;
- **Передать** выбранному проекту — устройство чужой брони или идущей сборки; повторный клик подтверждает, идущая там сборка останавливается (`reserve --force` тулинга);
- **Снять бронь**;
- **Остановить сборку** (с подтверждением) или **Убрать зависший лиз**.

Плагин не привязан к конкретной копии: список проектов и тулинг берутся из реестра. Каждое действие выполняет `scripts/projectTooling.js` той копии, от имени которой оно делается: бронь — из копии-получателя, снятие брони и лиза — из копии-владельца, а если её папки нет — с `--force` из любой другой зарегистрированной копии. Сам плагин реестр не пишет.

- Host (`index.js`, `normalize.js`): `GET /device-reservations/devices` и `POST /device-reservations/action` за стандартной проверкой `connection.requestRejection`. Список — `device list --json` первой зарегистрированной копии с тулингом (опрос adb / simctl / devicectl, брони не меняет, ~3–7 с), реестр копий из `ledgerPath`, живость лиза по {pid, bootId, startTime} — тем же правилом, что и тулинг. Собственный `listing` тулинга не используется: он считает «моё/чужое» относительно копии, в которой запущен. Действия выполняются по одному, ответ несёт свежий список.
- Client (`client.js`): слот `conversation.composer.dock` (order 3), только иконка.

Настройки — в `cordis.patch.yml` профиля:

```yaml
- id: device-reservations
  config:
    checkout: ''                       # пусто — первая копия из реестра с тулингом; иначе путь для списка
    ledgerPath: ~/.looky/ledger.json
    node: ''                           # пусто — Node рантайма DSH
    timeoutMs: 30000                   # сбор списка
    actionTimeoutMs: 120000            # одно действие (передача ждёт остановки сборки)
```

Подключение: Plugins → Add plugin → путь к этой папке (при HMR применяется сразу), либо `plugins/install.sh` при закрытом DSH — он добавляет в `~/.dsh` и `~/.dsh-dev` зависимость `link:` и бандл после последнего `@local/`-бандла.

Проверки: `node --test tests/`.
